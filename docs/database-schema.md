1. Database Setup: Extensions & Enums
Before creating tables, we need to enable the necessary extensions (like PostGIS) and define custom enumerations (Enums) to strictly control allowed values and optimize storage.

SQL
-- Enable PostGIS for geographic calculations (distances, radius, etc.)
CREATE EXTENSION IF NOT EXISTS postgis;

-- Define User Roles
CREATE TYPE user_role AS ENUM ('citizen', 'admin', 'field_worker');

-- Define Complaint Statuses
CREATE TYPE complaint_status AS ENUM (
    'pending_ai_review', -- Initial state for AI screening
    'open',              -- Validated, awaiting assignment
    'assigned',          -- Worker assigned
    'in_progress',       -- Worker actively fixing
    'resolved',          -- Fixed, pending verification
    'closed',            -- Verified and archived
    'rejected'           -- Spam or invalid
);

-- Define Priority Levels
CREATE TYPE priority_level AS ENUM ('low', 'medium', 'high', 'critical');

-- Define Worker Assignment Status
CREATE TYPE assignment_status AS ENUM ('pending', 'accepted', 'en_route', 'completed', 'failed');
2. Table Schemas
A. Core Users & Categories
users
Stores all platform users. In Supabase, this table usually links 1-to-1 with the built-in auth.users table for authentication.

SQL
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    role user_role NOT NULL DEFAULT 'citizen',
    full_name VARCHAR(255) NOT NULL,
    phone_number VARCHAR(20),
    email VARCHAR(255) UNIQUE NOT NULL,
    -- PostGIS: Stores the worker's last known location for smart dispatching
    last_known_location GEOMETRY(Point, 4326), 
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ -- Soft delete
);
categories
Stores grievance types. Uses JSONB for seamless multilingual support without needing complex translation tables.

SQL
CREATE TABLE categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    -- JSONB example: {"en": "Pothole", "es": "Bache", "hi": "गड्ढा"}
    name_translations JSONB NOT NULL,
    default_priority priority_level DEFAULT 'medium',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
B. Complaints (The Core Domain)
complaints
The central table for grievances. Heavily integrated with PostGIS and AI columns.

SQL
CREATE TABLE complaints (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    reporter_id UUID REFERENCES users(id) ON DELETE SET NULL,
    category_id UUID REFERENCES categories(id),
    
    title VARCHAR(255) NOT NULL,
    description TEXT,
    
    -- Geolocation & Mapping
    location GEOMETRY(Point, 4326) NOT NULL,
    address_text TEXT, -- Reverse geocoded human-readable address
    
    -- Status & Priority
    status complaint_status DEFAULT 'pending_ai_review',
    priority priority_level DEFAULT 'low',
    is_escalated BOOLEAN DEFAULT FALSE,
    upvote_count INTEGER DEFAULT 0,
    
    -- AI Features
    ai_priority_score DECIMAL(5,2), -- AI's calculated urgency (e.g., 85.50)
    ai_metadata JSONB,              -- Store detected sentiment, entities, etc.
    duplicate_of_id UUID REFERENCES complaints(id), -- Self-referencing FK for duplicates
    
    -- Audit & Soft Deletes
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);
complaint_media
Stores Cloudinary image URLs. Separated from complaints to allow multiple images per grievance.

SQL
CREATE TABLE complaint_media (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    complaint_id UUID REFERENCES complaints(id) ON DELETE CASCADE,
    media_url TEXT NOT NULL,
    ai_image_tags JSONB, -- Tags generated by Cloudinary/AI (e.g., ["water", "pipe_burst"])
    uploaded_at TIMESTAMPTZ DEFAULT NOW()
);
C. Interactions & Tracking
complaint_upvotes
Allows citizens to upvote public issues (like crowdsourcing priority).

SQL
CREATE TABLE complaint_upvotes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    complaint_id UUID REFERENCES complaints(id) ON DELETE CASCADE,
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(complaint_id, user_id) -- Prevents a user from upvoting twice
);
worker_assignments
Maps field workers to complaints. Essential for task management.

SQL
CREATE TABLE worker_assignments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    complaint_id UUID REFERENCES complaints(id) ON DELETE CASCADE,
    worker_id UUID REFERENCES users(id) ON DELETE CASCADE,
    status assignment_status DEFAULT 'pending',
    assigned_by UUID REFERENCES users(id), -- Admin who assigned it (if manual)
    assigned_at TIMESTAMPTZ DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    resolution_notes TEXT
);
complaint_status_history
Audit log. Every time a complaint changes status, a record is added here. Essential for tracking SLAs (Service Level Agreements) and user transparency.

SQL
CREATE TABLE complaint_status_history (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    complaint_id UUID REFERENCES complaints(id) ON DELETE CASCADE,
    changed_by UUID REFERENCES users(id) ON DELETE SET NULL,
    old_status complaint_status,
    new_status complaint_status NOT NULL,
    comment TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
notifications
System alerts for users (e.g., "Your complaint has been resolved").

SQL
CREATE TABLE notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    title_translations JSONB NOT NULL,   -- Multilingual title
    message_translations JSONB NOT NULL, -- Multilingual body
    is_read BOOLEAN DEFAULT FALSE,
    reference_id UUID, -- ID of the complaint/assignment this relates to
    created_at TIMESTAMPTZ DEFAULT NOW()
);
3. Highly Optimized Indexes
Indexes are crucial for database performance, especially with geolocation and AI lookups.

SQL
-- PostGIS Spatial Index for lightning-fast map queries (e.g., "Find complaints within 5km")
CREATE INDEX idx_complaints_location ON complaints USING GIST (location);
CREATE INDEX idx_users_location ON users USING GIST (last_known_location);

-- B-Tree Indexes for Foreign Keys (Speeds up JOINs)
CREATE INDEX idx_complaints_reporter ON complaints(reporter_id);
CREATE INDEX idx_complaints_category ON complaints(category_id);
CREATE INDEX idx_worker_assignments_worker ON worker_assignments(worker_id);

-- Partial Indexes for Soft Deletes (Only indexes active records)
CREATE INDEX idx_active_complaints ON complaints(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_active_users ON users(role) WHERE deleted_at IS NULL;

-- JSONB Indexing (Allows fast querying inside JSON objects, useful for AI metadata)
CREATE INDEX idx_complaints_ai_metadata ON complaints USING GIN (ai_metadata);
4. Architectural Explanations
How Tables Interact (The Flow)
Reporting: A Citizen (users) reports an issue. A row is created in complaints and images are saved to complaint_media.

AI Processing: The backend runs AI tasks, updating the complaints table with an ai_priority_score and checking if it matches an existing issue (updating duplicate_of_id).

Tracking: Other citizens can like the issue, inserting rows into complaint_upvotes (which increments the upvote_count on the main table via a database trigger).

Dispatch: An Admin (users) assigns a Field Worker (users). A row goes into worker_assignments.

Resolution: The worker finishes the job. A row is added to complaint_status_history, the complaints.status changes to 'resolved', and a notifications row is generated for the citizen.

How AI Features are Supported
AI Duplicate Detection: The duplicate_of_id column allows you to group duplicate complaints together. The AI will query existing complaints, and if a 95% similarity match is found, it links the new complaint to the original one instead of cluttering the worker's queue.

AI Auto-Categorization & Priority: The ai_metadata (JSONB) column acts as a flexible bucket. Your AI can dump extracted keywords, sentiment analysis (e.g., {"sentiment": "angry", "keywords": ["pipe", "water", "flooding"]}), and an ai_priority_score (0-100 scale).

AI Worker Dispatch (Future): The last_known_location in the users table combined with PostGIS allows the AI to calculate the exact distance between an incoming complaint and the nearest available field worker.

Soft Delete Strategy
Notice the deleted_at column on core tables. We never actually DELETE data.
If an admin deletes a user or a spam complaint, we simply set deleted_at = NOW(). This ensures database integrity (foreign keys don't break) and allows data recovery, while our Partial Indexes ensure that deleted rows don't slow down everyday queries.
